# 资产工坊

本地中文资产工作台。网页与 Codex 共用文件、资产目录和持久任务，不需要 GPT API。

**当前使用入口**：[中文新手开始](skill/references/新手开始.md)、[能力索引](skill/references/索引.md)、[路径/打开/迁移](skill/references/运行与迁移.md)。完整现状与待办看 [系统全景](docs/系统全景与实施路线.md)，本次三个视角的审核与取舍看 [审核处理](docs/三视角审核与采纳.md)。

## 打开

告诉 Codex“用 asset-workbench 打开资产工坊”，或双击 `启动资产工坊.cmd`。全局入口 open 关闭旧空闲服务后启动一个隐藏进程；有活动任务则复用。程序与数据地址由全局 Skill 的 workbench.json 绑定，可分盘。
页面：<http://127.0.0.1:4380>。项目：`D:/godotGames/AssetWorkbench`。

## 三个入口

1. **生成模型**：Lux3D 国际站，文字/参考图 → 实时报价 → 明确提交 → 原任务跟踪 → 回库。已配置官方运行时，开发期间没有提交收费生成任务；本轮未实际验证远端生成。
2. **添加动作**：选择带骨架的模型，多选库中已有片段，生成新 GLB。同静止骨架直接复制动画，保留目标网格和贴图。不同骨架提示人工适配，可准备 FBX 到 Mixamo/AccuRIG，并从同一任务回传。
3. **导出序列帧**：在网页直接旋转、缩放和平移取景，确认后生成当前构图的 GIF。保存时使用这批原 PNG，包含分页图集、帧时间/锚点 JSON、GIF 和离线 HTML 预览 ZIP。原来的 Blender 批量渲染仍可通过 CLI 调用。

资产库能查看模型、骨架名单、内嵌贴图、动作片段和来源。资源状态是“待查看 / 可复用 / 有问题”。任务完成不自动等同于质量通过。

## 新人最短路径

- 选择当前对外模型，或导入自己的角色。旧模型在“其他”保留，当前列表不强制依赖某个历史名称。
- 点“添加动作”，按动作类型比较不同来源在目标模型上的实际效果，选用后打包。
- 没有合适动作：点击“去 Mixamo 获取新动作” → 下载上传用 FBX → 打开 Mixamo 选动作并下载 → 批量导回 FBX。入口直达：<http://127.0.0.1:4380/?panel=mixamo>。
- 导出图片：选模型和动作 → 调整画面 → 确认并生成 GIF → 保存并下载序列帧。入口直达：<http://127.0.0.1:4380/?panel=frames>。变更构图后旧 GIF 标记为待重新确认，当前构图完成后才允许保存。
- 第一次 Mixamo 下载选 With Skin，后续同角色动作可 Without Skin。GLB 不能直接上传 Mixamo。
- 轻量上传不嵌贴图；网站白模不等于原资产丢失贴图。成品以保留材质的目标模型为基准合并。
- GLTF/OBJ 有依赖时在“资源管理”点击“导入带贴图的完整文件夹”，保留 BIN、MTL 和贴图的相对目录。
- 工作台：用连线展示来源模型 → 3D 模型 → N 个动作 → 2D 动作集。点节点或从圆点连到下一步，继续制作；实线表示实际入库依赖。
- 多动作图片：同模型同构图的序列帧归为一套 2D 动作集，打开直接洋葱播放。可调整顺序、重复加入、慢放和循环验收，顺序自动保存。文件与 AI 判断放在折叠详情中。
- 全局 Skill 通过 asset-flow / sprite-set / onion-preview / sprite-playback 共用这些数据，操作见 skill/references/资产工作流.md。
- “复制给 Codex”将资产或任务编号复制到剪贴板，粘贴到 Codex 对话继续。网页不需要额外 AI 账户。

## 已有资源

- 用户 Lux3D 原始主角，两个用户下载的 Mixamo 动作版本。
- 新产物：41 骨骼主角的两个独立动作组合 GLB。99,530 三角面；GLB 中拆分 UV 等后的顶点计数为 72,729。1 张内嵌图片被纹理/材质使用；不把纹理槽数量混作图片数量。
- Quaternius 男、女角色各 43 个片段（42 动作 + 参考姿态）；长弓资源 39 个片段，沿用现有 Motion Studio 的适配。
- 双动作序列帧样例：256 × 256、6 fps、44 帧。低帧率用于快速浏览流程；实际制作可选默认 512 × 512、24 fps。

旧的自制 27 骨架和手工编造动作没有加入本库。曾生成的动作顺序错误样例已标记“有问题”，保留记录；修正版本为独立新资产。

## Codex 工具

全局技能 `asset-workbench` 安装于 `C:/Users/Admin/.codex/skills/asset-workbench`；新会话可发现，当前会话也可直接使用项目 CLI。

```powershell
node scripts/cli.mjs state
node scripts/cli.mjs compose request.json
```

CLI、MCP 和页面调用同一个 HTTP 服务。MCP 服务源码已提供：`scripts/mcp.mjs`。可选注册片段见 `skill/references/operations.md`；本轮没有擅自更改全局 MCP 配置，CLI 路线已可用。

## 数据与运行

- Node 26、Blender 5.1、Python 3.11 + Pillow；前端 React + Three.js + Vite。
- `data/workbench.sqlite`：资产、任务、步骤记录和报价；`data/packages`：原始包；`data/assets`：已发布产物；`data/work`：制作日志和过程文件。
- 数据仅存本机。全局 pack 命令生成包含 Skill、程序和完整资产的可恢复迁移包，采用 SQLite 一致备份与逐文件哈希。restore 到空目录后安装依赖、bind、doctor、open；旧库不删，不把原始 Key 放进包。
- 服务只监听 127.0.0.1。使用全局 stop 管理已绑定服务，核对路径/库 ID/进程，不按端口盲杀其他项目。
- Lux3D key 只读现有私有配置文件；不发送给网页。报价存在进程内，服务重启需刷新未提交报价。
- 本地任务中断可重试；已提交云端任务继续查原 taskId；未知提交结果需要核对，不能自动重复收费。
- Blender 单任务处理；网站等待释放队列；取消会终止该本地 Blender 子进程。

## 当前边界

- 同静止骨架直接组合 GLB。已知人形骨架支持保留目标骨长的本地 FK 适配，保留原动作时间；结果需查看脚底接触、穿插和姿态，不等于通用自动重定向。无法映射的骨架保存任务，交由成熟工具或网站适配后回库。
- 没有新增自制动作，没有自动混合上下半身动作；“多个动作”指多个独立片段。
- 序列帧当前单角色骨架；多个独立角色需要拆开。输出最多 720 帧/任务。
- 网页所见即所得使用 Three.js 当前视图逐帧捕获，缓存键包含模型哈希、动作、相机、尺寸和帧率；GIF 编码用本地 Pillow。保存原帧时不再次渲染。Blender CLI 渲染仍采用 Cycles 16 samples + 降噪。
- 本轮已完成前端构建、已有资源入库、真实合并、真实渲染与 FBX 输出。没有新增或运行测试套件。
- 浏览器工具最初遇到 Windows sandbox ACL 启动错误；后续已用本机 Chrome 渲染四个实际页面和窄屏预览，检查显示。没有把这当作全部流程的测试结果。

## 新人界面

- 页面入口为 `src/SimpleApp.jsx`，统一样式为 `src/studio.css`；旧版 `main.jsx/style.css/simple.css` 未被当前入口加载。
- 选择模型 → 点击动作类型 → 切换来源、左右同步试播 → 选用满意版本 → 打包。原有动作默认保留；骨架与处理细节收在资源管理。
- 同类动作按来源模型和真实片段编号区分，能同时选用多个版本。左边显示来源模型，右边显示当前目标模型的实际适配；共用播放、暂停和拖动进度。无法适配时显示具体原因。
- 首次试播在独立后台任务中处理，结果缓存在 `data/previews/motions`，记录在 SQLite 的 `previews` 中。切换时只替换目标动画，模型和贴图继续复用。最终打包读取相同的试播片段；试播不会向作品库堆积成品。
- UI 使用 Radix Primitives，Select 组合参考 shadcn/ui 官方源码；不需要额外 AI API。详见 [界面方案](docs/界面方案.md)。
- 缩略图来自实际模型。`node scripts/make_asset_posters.mjs` 补齐现有模型的缩略图，后续组合动作的结果继承目标缩略图。
- 战术主角的身体材质已修正为不透明，修复前版本保留在历史中。已修复的旧资源下载入口会返回修复版。
