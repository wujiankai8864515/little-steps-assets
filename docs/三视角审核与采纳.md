# 本次三视角审核与取舍

2026-10-09。用户新增授权三个一次性审核。三个代理均继承主代理模型与推理设置，只读方案/代码，没有创建代理、运行服务或测试。收到最终报告后均已停止；后续无新授权不再调用。

审核基准：[系统全景与实施路线](系统全景与实施路线.md)。各审核发现说明如下；“采纳”表示落实最小必要修正，不表示扩成另一个平台。

## 熟悉系统的人类使用者

| 问题、证据与影响 | 决定 | 实施 |
|---|---|---|
| asset-plan 阶段单一、无计划检索、导回未关联；换 AI 会重复制作 | 采纳 | plans 检索；planId 贯穿上传/导回/制作；真实任务阶段、产物和交接；当前选择摘要隔离旧分支 |
| targetQuality 一直 unknown，审过的目标适用经验无法积累 | 采纳 | motion-quality 记录模型/动作哈希、预览版本、用途、证据和备注；目录返回实际适用记录 |
| 最后交付各 AI 手写字段不一，易漏锚点/许可/待办 | 采纳 | handoff 生成统一 JSON 与中文说明；引擎接入仍由具体游戏项目负责 |
| 精确旧资源网页自动切新版，与交接哈希不符 | 采纳 | 目录链接 exact=1；网页遵守，另有查看推荐新版按钮；精确下载同步 |
| 迁移保留库 ID，若只核对 ID 可能继续使用旧盘 | 采纳 | 程序/数据路径、库 ID、进程三方核对；旧服务忙则不改绑定 |
| 解压成功不代表 Node/Pillow 等依赖齐全 | 采纳 | 可恢复包、逐文件哈希、依赖步骤、doctor 分能力说明；输出禁止位于源目录内 |
| 洋葱皮只看首尾不足，需要实际切换帧和衔接用途 | 采纳 | pairs、intent、rootMotionPolicy 持久化；窗口临时拖动与保存新证据分离 |

## 完全不熟悉系统的人类

| 问题、证据与影响 | 决定 | 实施 |
|---|---|---|
| 所有试播错误只有重试，新手会反复失败 | 采纳 | 无骨架→绑定；needs_input→换来源；临时失败→重试；原因折叠；空搜索有获取动作入口 |
| 校对要求多个同构图包，逐段导出易取景不同 | 采纳 | 当前构图批量选择动作，实际完成后直接带入校对 |
| AI 判断需外部对话，页面不能假装自动进行 | 采纳 | “复制给 Codex 判断”及粘贴提示；仅保存真实结论后显示已判断 |
| 标“有问题”后从作品中消失，难以找回 | 采纳 | 其他分类保留有问题和历史资产，可在资源管理恢复状态 |
| 另一个浏览器不能从本地存储找回未完成任务 | 部分采纳 | 从服务任务显示紧凑续作入口，打开已有任务管理；不新增首页/教学流程引擎 |
| 迁移让新人填两个路径太复杂 | 采纳 | restore 支持一个 destination，下面分程序/资产；高级参数仍保留 |
| README 的例子/按钮与当前数据不符 | 采纳 | 中文新手页使用稳定流程；文件夹导入补真实入口；旧双动作模型不再强制写入起步步骤 |
| 成功后下一步不清楚 | 采纳 | 生成→加动作，组装→导出图片，批量帧→衔接校对；不新增导航页面 |

## 完全陌生、推理较弱的 AI 调用者

| 问题、证据与影响 | 决定 | 实施 |
|---|---|---|
| plan 浅合并 motions 会丢掉其它职责；阶段始终待试播 | 采纳 | 按 key 合并、motionSelections、replaceMotions 显式整体替换；无效引用给缺口；跟踪真实阶段 |
| needs_input 的 FBX 实际可用，与“仅成功才有输出”矛盾 | 采纳 | artifactsReady、下一步官网指引；文档区分中间产物/整体完成；业务错误不一律建议 doctor |
| preview 不接受精确 ref，检索和组装可能指不同源 | 采纳 | 共用 resolvePick；search 返回 previewRequest；目录状态和适用记录按同一精确源查询 |
| 多 FBX 单次导入可能只处理第一个 | 采纳最小方案 | API 拒绝不明确的多独立入口，网页逐文件；不再增加重复 import-batch 命令 |
| submit 响应丢失，调用者没有 quoteId 找原任务短路 | 采纳 | quote-status、同 quoteId 返回原 job；不再次发出收费请求 |
| 能力索引缺少输入/返回/完成/失败契约 | 采纳 | 机器索引和中文按需页，最短链与交付；保持一张命令定义表 |
| 洋葱皮没有预期关系，可能误判合理位移 | 采纳 | intent/rootMotionPolicy、实际比较帧；anchors/clipping/continuity/footSlip 分项和 not_assessed；保存校验 reportHash |
| 迁移“完成”混淆文件恢复、绑定和可用 | 采纳 | phase=restored_unbound/bound/service_bound，结构化 bind 下一步，doctor 按能力报告依赖 |

## 本轮没有引入的扩展

三位均不建议为了完全无人化增加通用自动绑骨、私有 Mixamo 接口、后台 AI、向量数据库、独立索引服务、通用引擎插件和自动两两动作比较。保留这些边界：当前实现成本高、维护负担大，不能直接解决本次可用性问题。

对“任务续接”选择真实记录加阶段推导，不加入完整工作流引擎；对“AI 校对”选择可追踪图片和调用者判断，不引入新的付费模型；对迁移选择可恢复包和依赖说明，不把 Blender/Chrome 等软件复制进巨大安装包。

## 实施证据

代码、中文文档、全局副本、构建以及实际校对/交接结果在《实施进度》更新。没有新收费模型生成；文件迁移能力尚未代表已把用户资产搬到另一个盘。没有新增或运行测试套件，不能把静态审核/构建当作所有骨架、游戏运行和迁移故障已通过。
