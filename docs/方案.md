# 资产工坊 v1 实施方案

日期：2026-10-08。状态：唯一审核结束，实施中。以下初稿与《审核处理.md》《成熟工具调研.md》共同阅读；冲突处以后两者的实施决定为准。

## 产品目标

本机运行、中文界面、面向新人的资产工作台。三个生产入口共用资产、任务与来源记录：

1. 生成模型：Lux3D 文本/参考图生成；平台适配器可替换；其他平台先提供明确的人工导入入口。
2. 添加动作：指定一个已有模型，选择多个已有动作，导出包含多个独立片段的新 GLB。缺骨架或不兼容时提供 Mixamo FBX 导出、网站操作说明、结果导入入口。
3. 三维转序列帧：从已入库角色选择动作、视角、尺寸和帧率，输出透明 PNG 序列、图集、元数据和预览 ZIP。

前期接受人工登录、绑骨标记和动作选择。人工步骤记录为“需要处理”，不会伪装成自动完成。保留模型、贴图、UV、面部和关键细节；默认不减面、不重新生成动作。

## 架构

- 新项目 D:/godotGames/AssetWorkbench，读取并复用已有资产，保留原 Motion Studio 和拳击游戏。
- Vite + React + Three.js 前端。参考 Anthropic frontend-design 的主体优先、克制视觉、明确文案和空状态；参考 shadcn/ui 的侧栏、表单、Sheet 与任务状态组织，适用部分用现成 Radix/lucide 组件。浅色中性界面，模型舞台为主要视觉。
- Node 本地 HTTP 服务，绑定 127.0.0.1；SQLite 记录资产、动作、任务、事件、平台报价；文件保存在独立 data 目录。
- Blender 独立后台进程处理导入、动作合并/重定向、Mixamo FBX 和序列帧。单个本地重任务队列，避免多个 Blender 争抢资源。
- 全局 skill 与命令行客户端调用同一个服务。MCP 提供结构化工具入口；网页提供“复制给 Codex”的任务说明。自然语言仍在 Codex 中交互，无 GPT API 依赖。
- Lux3D 调用已安装官方 Python 运行时；密钥从已有私有凭据文件读取，绝不发给浏览器或写入项目。报价与明确的提交按钮分开；本次开发不提交收费生成任务。

## 资产和任务

Asset: id, name, kind(model/motion/image/sprites/export), immutable file, SHA256, parentIds, source, metadata, createdAt。
模型 metadata 包含三角面数、贴图、骨架层级/静止矩阵摘要、独立动画列表。贴图归属于模型；原始文件保留。
Motion: id, assetId, clipName, duration, rigSignature, tags。模型动画自动成为可检索动作；初期用名称/标签搜索，无向量数据库。
Job: id, type, inputIds, settings, state, stage, completed/total, outputs, error, remoteTaskId, createdAt/updatedAt。
状态：queued/running/needs_input/interrupted/failed/succeeded/cancelled。进度按导入步骤、片段数或渲染帧数记录；生成服务未给进度时显示阶段和耗时。
任务创建立即落盘，原始文件不可变。进程重启时运行中的本地任务变 interrupted，显式重试；远端任务有 taskId 则继续查原任务，提交结果未知时禁止自动重新收费提交。

## 动作处理边界

1. 同骨架、同静止姿势：直接把所选原始动作放到目标骨架，保留材质、顶点、权重。
2. 已知人形骨架：按语义骨名与层级映射，保留目标骨长，用源静止旋转差驱动目标，根位移按尺寸比例适配。烘焙属于适配已有动作，不编造新动作。
3. 映射缺失、A/T 校准不确定、源有不支持的非根平移/伸缩：任务明确 needs_input，提供缺失骨骼和 Mixamo 路线，不做貌似成功的猜测。
4. 初始覆盖当前主角 Mixamo 骨架与现有 Quaternius 骨架；扩展通过保存配置积累。
5. 默认保留根运动；原地模式是明确选项；不默认镜像、裁剪或改变动作速度。

## 序列帧

正交相机默认 512px/24fps、透明背景；取整个片段统一包围范围、统一中心和脚底参考，固定相机和图集锚点。按时间采样，循环不重复终点，非循环保留终点。所有帧的模型、灯光和视角一致。输出上限用于防止误操作，超限给出具体调整建议。
Blender Eevee 渲染 PNG；Python 标准库 ZIP 打包；图集用已存在可用 Pillow 或项目明确依赖。预览图与 ZIP 登记为资产。

## 页面

固定侧栏：资产库、生成模型、添加动作、导出序列帧；底部任务按钮和设置。
资产库：搜索、分类、小卡片、详情舞台；首次进入有“用示例开始”和“导入模型”。模型详情直接提供“添加动作”和“导出序列帧”。
生成：平台选择、文本/图片、少量默认选项、实时报价、提交、结果回库。
动作：选角色 → 搜索/多选动作 → 创建新版本；一旁显示原始动作预览和兼容提示。Mixamo 人工步骤只在需要时展开。
序列帧：选模型/动作、方向/尺寸/帧率；创建任务、查看进度、下载。
任务抽屉：阶段、逐项进度、来源、产物、失败原因、下一步和复制给 Codex。刷新后恢复。
技术信息放“详情”；常用页面用中文动作词，不把骨架哈希、接口端点放在新人主流程。

## 唯一审核与实施顺序

方案 → 伪代码 → 一个继承主代理模型及推理设置的只读审核代理 → 保存意见并结束该代理 → 修订 → 单代理实施。
本次只允许此一次审核，审核者不得创建代理，实施及后续工作不再创建代理。
实施顺序：数据与队列；Blender 工具；网页；Lux3D 适配；Codex 入口；启动和实际资产产物。按用户要求不向其提问；没有新素材生成规格/预算时仅完成生成能力，不消费 credits。
