# 资产工坊纯代码迁移说明

## 2026-10-14 当前补充

本仓库已增加 web/ Pages 云端版，默认入口与部署说明见 [Pages云端方案](Pages云端方案.md)。当前不恢复旧数据库、不将模型克隆到 Mac。源码重新打包会包含云端前端与部署 YAML；以下保留原 Windows 本机迁移路线。

更新日期：2026-10-09。

## 这个包是什么

这是现有 AssetWorkbench 平台的源码快照，不是带资源的资产库迁移包，也不是无需安装依赖的离线安装包。

包含前端、Node 后台、GLB 动作处理、Blender/Python 工作脚本、CLI、stdio MCP、全局 Skill 源码、锁定依赖表、中文设计和操作文档，以及许可证说明。

不包含模型、动作文件、参考图片、贴图、序列帧、封面、SQLite 数据库、工作台记录、任务和报价记录、缓存、日志、构建产物 dist、node_modules、Blender/Python/Chrome 安装程序、Lux3D 官方插件及其私有运行时、账号凭据。

旧电脑的 `skill/references/workbench.json` 路径绑定没有带入。新电脑必须创建自己的库和绑定，不能复制旧库 ID，也不能先双击旧启动入口。

包根目录的 `代码包清单.json` 给出每个源码文件的 SHA256；ZIP 同目录的 `.zip.sha256` 给出整个代码包的 SHA256。

## 当前实现与后续目标

当前是本机运行的 React/Three.js 前端＋Node 服务＋SQLite/文件目录；CLI、Skill、stdio MCP 共用本机服务。

以下是已讨论、尚未实施的后续架构：一个仓库内拆分“公开展示站”和“本地工作台”；GitHub Pages 只展示确认发布的带动作模型和序列帧；Releases 分发资产包；发布清单提供封面、版本和下载地址。本代码包没有已部署的 Pages 工程、自动公开发布闭环或远程 MCP，不能把这个包原样放到 Pages 就当作完整平台。

历史 README 和审核文档保留了当时的模型名、库 ID、路径与验收记录，只是历史说明，文件本身没有包含那些资源。当前全景见 `docs/系统全景与实施路线.md`；纯代码初始化以本文为准。

## 先安装依赖

以 Windows 为主要运行环境。解压到自己的新目录，例如 `E:/工具/AssetWorkbench`。下列命令在解压后的项目根目录执行。

基础功能需要 Node.js 26、npm 和联网安装依赖；不需要 GPT API。

```powershell
npm ci --no-audit --no-fund
npm run build
```

按需准备外部工具：

| 功能 | 依赖 |
|---|---|
| 网页、检索、带骨骼 GLB 动作组装 | Node 和上述 npm 依赖、dist |
| FBX 等格式导入、Mixamo 上传文件、Blender 渲染 | Blender，默认查找 Blender 5.1 安装路径，可用 BLENDER_PATH 指定 |
| 网页当前构图批量出帧、GIF、图集及洋葱皮证据 | Python 3.11＋Pillow；批量捕获还需要 Chrome 和 Playwright |
| 生成新模型 | 另行安装官方 Aholo Lux3D 插件、运行其 setup_runtime.py，并在目标电脑配置自己的账号 |

Python 和 Blender 路径不同时，在启动服务前设置实际路径：

```powershell
$env:PYTHON_PATH = 'C:/你的Python目录/python.exe'
$env:BLENDER_PATH = 'C:/你的Blender目录/blender.exe'
$env:WORKBENCH_CHROME = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
& $env:PYTHON_PATH -m pip install Pillow
```

Playwright 可以用目标电脑 Codex 自带运行时；如果没有，安装到项目依赖目录，再设置路径：

```powershell
npm install --no-save --package-lock=false playwright
$env:WORKBENCH_PLAYWRIGHT = (Resolve-Path './node_modules/playwright/index.mjs').Path
```

批量捕获脚本明确使用上述 Chrome 安装程序，不要求下载另一个浏览器。这里给的是依赖配置方法，不表示目标电脑已经安装成功或经过功能验收。

Lux3D 凭据保存在目标用户自己的私有配置；不要把 Key 写进网页、Skill、代码仓库或发布包。Mixamo 仍需要使用者自己的网页登录和必要人工步骤。模型生成费用按平台实时报价确认，本包不包含额度。

## 在新目录创建空库并启动

这是“不带资源”的交付，因此第一次启动得到新的空资产库；不是恢复旧库。后续手动导入自己的模型和动作。

先使用一个空的本地数据目录和空闲端口。下面选择项目自己的 data，不指向原电脑资产库：

```powershell
$env:WORKBENCH_DATA_DIR = Join-Path (Get-Location).Path 'data'
$env:PORT = '4380'
npm start
```

后台首次运行会初始化 SQLite 和新的 libraryId。打开 `http://127.0.0.1:4380`。

如果端口已有别的项目使用，选择另一空闲端口并同步下节 BaseUrl；不要为了迁移强杀现有服务。不要运行 `npm run seed`：它是旧电脑历史样例入库脚本，包含旧资源路径，本包没有相应资源。

## 安装全局 Skill，并保存目标电脑路径

保持上面的服务运行，在另一个 PowerShell 窗口进入同一个项目目录：

```powershell
& './scripts/install-skill.ps1' -DataRoot (Join-Path (Get-Location).Path 'data') -BaseUrl 'http://127.0.0.1:4380'
```

如果使用了其他数据目录或端口，传入实际值。安装脚本核对正在运行服务的程序路径、数据路径及真实 libraryId，然后生成新的绑定并同步 Skill。

默认 Skill 位置为用户目录 `.codex/skills/asset-workbench`；设置 CODEX_HOME 时使用其 skills 子目录。若目标电脑已经装有同名 Skill，先备份其目录和绑定；执行本步骤代表明确切换到新代码和新库。本代码包本身不会修改任何现有全局绑定。

不使用 `-Offline` 初始化空库：它是完整资产恢复包的安装方式，需要已经恢复的数据库和库身份。

### 后续按需指定依赖位置

首次安装后，向 Skill 的 bind 命令传环境字段，使以后自动启动仍使用正确工具路径。创建 UTF-8 的 `环境绑定.json`，将占位地址换成实际文件地址：

```json
{
  "environment": {
    "PYTHON_PATH": "C:/你的Python目录/python.exe",
    "BLENDER_PATH": "C:/你的Blender目录/blender.exe",
    "WORKBENCH_CHROME": "C:/Program Files/Google/Chrome/Application/chrome.exe",
    "WORKBENCH_PLAYWRIGHT": "E:/工具/AssetWorkbench/node_modules/playwright/index.mjs"
  }
}
```

```powershell
$skillHome = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$skillEntry = Join-Path $skillHome 'skills/asset-workbench/scripts/workbench.mjs'
node $skillEntry bind './环境绑定.json'
node $skillEntry doctor
node $skillEntry open
```

bind 会检查库身份，在确认服务空闲且属于本库后关闭它；忙碌时拒绝切换。open 管理单实例，并返回页面地址。依赖缺失时只修复对应功能，不更换或伪造数据库。

安装完成后可以双击项目里的 `启动资产工坊.cmd`。迁移前已有全局 Skill 时不要直接双击：旧启动入口会优先使用已有绑定。

stdio MCP 可选入口是 `node scripts/mcp.mjs`，它需要正确的全局 Skill 绑定；客户端通过标准输入输出调用。本包不自动修改 Codex 的 MCP 配置，也不提供云端 HTTP MCP。

## 给接手 AI 的说明

1. 先读本文和项目 AGENTS.md，然后读 Skill 索引中本次任务对应的一页。
2. 不带资源是用户明确要求，不要找不到旧库就误报数据丢失，或复制原机资源来填充。
3. 不运行历史 seed，不自动添加示例动作，不把未审核资源当作已选用。
4. 当前接手目标是本地可运行和正确路径绑定；展示站拆分及 GitHub 发布属于后续任务，不能宣称已完成。
5. 原模型、面部、材质和来源要保留；不自行制造动作或新增收费生成。
6. 此次打包没有迁移账号，没有停掉原服务，没有改写原资产库或全局 Skill。

## 再次制作纯代码包

在项目根目录执行，output 必须在项目之外且不存在：

```powershell
python scripts/package-code.py --output 'E:/交付/AssetWorkbench-code-only.zip'
```

打包脚本采用源码目录与扩展名白名单，并排除 data、dist、node_modules、凭据和运行绑定；写入文件清单后逐文件读取校验。完整资产迁移仍走原 Skill 的 pack/restore，不能混用两个包。
