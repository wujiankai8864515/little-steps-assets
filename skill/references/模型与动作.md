# 模型、骨架和已有动作

## 共用事实

以 libraryId + ref + sha256 交接。模型用途 character、motion-source、working 与用户选用独立。先 asset-flow 读工作台；角色用途标记不能替代用户确认。精确引用不自动指向新版，preferredRevision 只作建议。带 exact=1 的网页用于看对应旧版本。

每个独立 FBX/BVH/GLB 单独 import。GLTF/OBJ 的模型、BIN/MTL 和图片才是一个依赖包，明确 entry 和 basePath。多个独立 FBX 混在单次 import 会被拒绝，避免只处理第一段。页面批量导入已逐文件建任务。

## 按既有模型配动作

1. search 模型 → inspect 候选和可见预览；用户已指定模型则直接精确定位。
2. search 动作，提供 modelId。不同来源同名动作都保留，不能只按“行走”字样决定。
3. 使用结果中的 previewRequest（modelId/ref）调用 preview。轮询 preview-status，queued/running 继续等待，succeeded 只是可以试播。
4. 查看来源与目标的实际效果。无法绑定时按 nextAction 完成骨架；无法适配时换来源或去成熟工具处理，不能让原模型播放冒充目标成功。
5. 需要积累适用经验时 motion-quality 保存 target 模型/源动作哈希、previewId、用途、证据和备注。选用按钮本身不等于严谨的质量判断。
6. 用户确认后优先 workspace-compose → wait → workspace-complete，输入同一 previewId 与精确片段。模型内片段用 workspace-selection。通用 compose 用 keepExisting=false 并列出全部明确选用片段；只有用户要求保留全部时才 true。导出工作台用 workspace-export，不能直接下载含隐藏片段的原文件。删除原模型片段仍可 remove-motions，生成副本，原动作库保留。

相同静止骨架直接保留网格/贴图二进制。已知人形 FK 适配保留目标骨长和原动作时间，但脚滑、握持与穿插要看。骨骼数量/名字相似不是通用兼容保证。不为本步骤减面，不创造新动作，不把不同动作放进同一文件解释为上下半身混合。

## 缺骨架、缺动作

upload 返回网站兼容 FBX。此任务会处于 needs_input，但 artifactsReady=true、outputs 中的 FBX 已经可以使用。下一步是官网人工处理并导回，不能不断 retry 重新导出。

网页入口 `/?panel=mixamo&model=模型ID`：准备上传文件 → 官网登录/标记/选择/下载 → 逐 FBX 导入。首次 With Skin，后续同角色可 Without Skin。GLB 不直接上传 Mixamo；轻量中转白模不表示原贴图丢失。import 带 handoffJobId 可继承模型及 planId。

先查已选范围；不足用 includeCandidates:true 检索待选，试播并确认后再复用。不足时按程序 docs 中带日期的成熟工具与许可说明查 ActorCore/AccuRIG、Quaternius、Rokoko 等。新消费与许可判断重新查官方，不承诺旧价格或免费条款永远有效，不开放第三方原动作分发。

## 缺形象时生成

查库和扩大中英文查询后仍没有合适形象，再准备全身、中性 T/A 姿态、服装时代/武器/风格和完整参考。quote 可能上传所选参考图；submit 才发起收费，必须有用户对该规格与价格/预算的明确授权。

保存 quoteId，再 submit。若响应丢失：立即 quote-status 查询该 quoteId → 获取 jobId → job/wait 跟踪原任务。重复同一 quoteId 会返回原任务，不重复收费；不得重新报价然后另提一单“试试看”。提交结果未知且没有远端 ID 时，保留 needs_input，去官网核对原任务后 resume。

生成结果未绑定时走补骨架流程。生成结束不等于形象、拓扑或可用动作验收通过。

网页播放：原始模型节点只展示静止外观。已选动作与候选试播均位于“已选动作”框内，各行 ▶ 指定片段；目标适用性确认仍对应精确 previewId。下载模型位于已选动作框下方。序列帧节点的播放和构图独立，不因动作试播改变相机。

## 多视角生成与草稿（2026-10-09）

- 逐张 import 图片，获得 image 资产 ID；网页支持一次选多张，每张单独导入任务，列表可补充、移除和排序。
- quote 使用 `operation:"image-to-3d",imageIds:["正面图ID","侧面图ID","背面图ID"]`。最多 32 张，按数组顺序传给 Lux3D 的 imgs，不能重复同一 ID。所有图片应表现同一个对象，避免互相冲突。
- 图片模式公开接口没有 prompt 参数：文字仅存为备注，不能声称文字将参与几何生成。纯文本模式使用 prompt；文生模型的可选参考最多一张。
- 不调用自动四视图生成。费用以这次具体 imageIds、version、faceCount 的实时报价为准；多图支持不等于额外消费已经授权。
- `generation-draft {}` 读草稿；`{patch:{modelName,prompt,references:[{assetId,name}]}}` 写入。网页上传未完成时用 `{jobId,name}`，每项只能二选一；参考图上限 32。它不触发上传、报价或收费。服务另记 lastJobId，关闭后继续跟踪原任务，不自动重新提交。
- 官方规格核对日期 2026-10-09：https://raw.githubusercontent.com/manycore-research/Aholo-Lux3D/master/plugins/codex/aholo-lux3d/skills/lux3d/core/contracts/lux3d-generation.v1.json 。规格未列绑骨操作；未找到免费绑骨官方承诺，不能声称关闭绑骨可省一笔 Lux3D 费用。缺骨架继续 Mixamo 或本地适配流程。

## 模型命名与一次绑骨（2026-10-09）

- 独立角色导入或生成前必须给用户指定的模型名称，1–60 字。不要从图片数量、提示词截断或文件名自动代替。网页先命名再上传；批量独立模型逐个命名。模型库卡片旁的铅笔可改名；工作台名称独立保留。
- 先 inspect 或 asset-flow.model.boneCount。模型有外形和贴图不代表已经有骨架，T 姿态也不能作为有骨架的证据。library 的 rigState 为 missing/present；present 不代表所有动作都兼容。
- 缺骨骼时 upload `{modelId,unrigged:true,textures:true}`。得到 artifactsReady 后使用既有输出；不重新生成外形，不发新的 Lux3D 生成任务。
- Mixamo Upload Character 上传这个 FBX 后按提示标记并自动绑定。网站完成后下载 FBX Binary / With Skin；可先下载 T-Pose，不必为了绑骨先选一批动作。官网操作和账号登录仍需人工，本地没有可承诺的官方 Mixamo API。
- 从原工作台“先绑定骨骼”导入返回文件，或 CLI import 同时给 handoffModelId、riggingReturn:true、可选 handoffJobId。这个显式用途与普通动作导入分开。
- 导入成功后先在节点内查看绑定角色的外观。确认同一个角色且外观和贴图完整，再 rig-adopt（字段见 operations）。有网格但没有骨骼、只有骨骼没有网格、没有绑定权重、源有贴图而返回无贴图的结果，不作为工作台已绑定角色接回。
- 接回的是同一模型的绑定版本，保留原始无骨骼文件，沿用模型家族与当前工作台。之后本地已有动作可反复试播/组装；同一角色不用为每段动作重复绑骨。动作的脚滑、穿插、武器握持仍需按目标预览判断。
- 接回动作幂等，但只允许接回来源匹配的当前工作台；已切换版本或有其他未完操作时停止覆盖，保留导回资产。导回中间结果仅入库，不代表工作台选用或质量通过。

官方说明：[Mixamo 上传和绑定角色](https://helpx.adobe.com/creative-cloud/help/mixamo-rigging-animation.html)（2026-10-09 核对）。Lux3D 当前公开生成契约未提供同时绑骨参数，不能用 Mixamo 的自动绑骨能力推断 Lux3D 输出已有骨骼。
