# 路径绑定、打开与资产库迁移

## 2026-10-14：当前以 Pages 为默认入口

无需恢复旧 Windows 库或启动本地服务。直接打开 https://wujiankai8864515.github.io/little-steps-assets/ ，连接 GitHub 后保存资源。Mac 获取代码时使用 --single-branch --branch main，不克隆 asset-library。当前说明见项目 docs/Pages云端方案.md；以下迁移步骤仅适用于原本机版本。

## 三个独立位置

1. **Skill**：通常在 C 盘用户的 `.codex/skills/asset-workbench`。里面只有入口、说明、脚本和绑定。
2. **程序**：绑定 `projectRoot`，包含 server/src/worker/dist/package-lock.json。
3. **资产库**：绑定 `dataRoot`，可以在 D/E 等盘；包含 SQLite、packages 原始文件、assets 成品、work 任务、previews 缓存。file 字段相对于此目录。

通过 location 查看真实地址，不把文档示例当配置。固定 libraryId 用于识别库；连接还会核对程序与数据的实际路径，因为同库副本可能具有相同 ID。

## 怎么打开与关闭

```powershell
node C:/Users/Admin/.codex/skills/asset-workbench/scripts/workbench.mjs open
node C:/Users/Admin/.codex/skills/asset-workbench/scripts/workbench.mjs stop
```

open 的顺序：核对数据库身份 → 管理锁 → 关闭旧空闲服务并等待 PID 退出 → 隐藏启动一个服务 → 检查身份 → 返回网址。调用者随后用 Codex 的浏览器工具打开返回地址，已有同网址标签页优先复用。Skill 命令不不断弹出浏览器窗口。

如果有排队、制作或预览任务，open 返回 reused=true 和活动任务，沿用现有进程；不打断制作。stop 同样会拒绝忙碌关闭。需要停止具体工作时由用户意图决定 cancel 原 job，不能为了打开页面取消所有任务。

普通 search/inspect/compose 等命令自动启动或复用服务，不重复重启。help/location/doctor 不会启动服务。不同项目占用端口时不会结束它。不要 taskkill 所有 node/blender，也不要按端口不看归属直接结束进程。

人类可双击绑定程序目录的 `启动资产工坊.cmd`，或告诉 Codex“打开资产工坊”。启动脚本优先读取全局入口的当前绑定。不要同时反复使用 npm start 手工另开实例。

## 已有库重新绑定

写请求（地址由用户实际选择）：

```json
{"projectRoot":"D:/资产工坊/程序","dataRoot":"E:/我的资产","baseUrl":"http://127.0.0.1:4380"}
```

运行 bind。目标必须已有合法数据库与程序，默认要求同一 libraryId；明确切换到另一个真实库时可传该库的 libraryId。旧服务有任务时保留旧绑定并返回原因。bind 不移动文件、不创建空库。

可选 environment 只支持依赖路径：BLENDER_PATH、PYTHON_PATH、WORKBENCH_CHROME、WORKBENCH_PLAYWRIGHT、LUX3D_SKILL_ROOT。不在此文件写 Key。绑定后 doctor 查看各能力依赖，再 open。

## 打包

用户说“资产库迁移”时，先 location 说明当前源地址、确定的目标盘。人类只需给一个目标文件夹；工具可在其下使用“程序”“资产”两个子目录。目标没有给出时可先生成迁移包，不猜测删除/移动路径。

pack 请求例：`{"output":"E:/备份/资产工坊-20261009.zip"}`。输出必须在程序、数据和 Skill 目录之外，不能覆盖已有 ZIP。

pack 会等待符合空闲条件，关闭旧服务，使用 SQLite backup 快照，流式打包并记录每文件 SHA256。包含当前全局 Skill、程序源码/已构建网页/锁定依赖表、数据库、原包、成品、任务资料与缓存。排除 node_modules、外部软件、账户凭据、进程锁、日志、过期报价。原服务此前在运行则打包结束恢复启动。出错保留 .partial 供诊断，不能把它当完成包。

这叫**可恢复迁移包**，不是含所有三维软件的离线安装包。不改变资源许可。

## 恢复和切换

同机请求：`{"archive":"E:/备份/资产工坊-20261009.zip","destination":"E:/新资产工坊"}`。也可分别传 projectRoot/dataRoot。

1. restore 检查 ZIP 路径、清单、重复条目和每文件哈希；只写空目录，拒绝覆盖现有库。
2. 成功返回 phase=restored_unbound、库 ID 和下一条 bind 参数；旧库保留、全局绑定未变。
3. 在新程序目录运行 `npm ci --no-audit --no-fund`。包内包含 dist；源码改动后再 `npm run build`。
4. 用原全局入口 bind 到新位置，再 doctor、open。不要在旧服务忙碌时切走它。
5. 跨机没有全局入口时：从 ZIP 取出 skill 文件夹，在 Python 下执行 `scripts/迁移资产库.py 请求.json`，mode=restore，指定 archive/projectRoot/dataRoot；恢复后在新程序目录执行 `scripts/install-skill.ps1 -DataRoot 新数据目录 -Offline`。然后运行全局 doctor/open。

restore 不自动删除半成品目录，也不删除旧库；失败后更换新的空目标重做或定位坏文件。未经用户要求，不清理旧库。

交接清单的绝对路径是历史快照，迁移后通过 refs 重新 inspect。数据库正式资产路径为相对地址，不能对全部提示词、日志做盲目字符串替换。

## 依赖与诊断

| 能力 | 需要 |
|---|---|
| 检索/网页/直接 GLB 操作 | Node 26、npm 锁定依赖、dist |
| FBX 导入/上传导出/Blender 渲染 | Blender；BLENDER_PATH 可指定 |
| 当前构图批量帧 | Python 3.11 + Pillow、Chrome、Playwright、dist |
| 洋葱皮证据 | Python + Pillow |
| 新模型生成 | 官方 Lux3D 插件及私有运行时、自己配置的账号；按实时报价授权 |

Pillow 缺失时在所选 Python 运行 `-m pip install Pillow`；Playwright 可用 Codex 自带路径，或在目标环境安装后将其 index.mjs 路径写入 WORKBENCH_PLAYWRIGHT。doctor 输出的是依赖可发现性，不是网站登录、生成额度或艺术质量证明。

doctor 报路径丢失：找原库或 restore，不新建空 SQLite。报告服务地址不匹配：核对 location 和旧服务路径，不强杀其他项目。服务未响应但进程仍在：查 dataRoot/server.err.log 与 service.json，确认归属后处理；不要因短暂无响应创建更多实例。

维护安装：`scripts/install-skill.ps1 -DataRoot 实际数据目录 -BaseUrl 实际服务地址`，在线模式核对服务真实路径。离线模式用于恢复包，最终全局入口仍会读取数据库真实 ID。


当前新增随库内容：workspaces 的人类名称、workspace-drafts 的关键操作、generation-drafts 的参考图顺序/原任务、asset-covers 的封面索引及 assets/covers 下 PNG、历史 sprites 的 preview-library.gif。它们包含在原有数据库与 data/assets 迁移范围，不另依赖 C 盘浏览器缓存。浏览器尚未同步的 pending 草稿应先恢复连接保存，再打包。
