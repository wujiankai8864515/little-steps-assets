# 工作台、选用范围与 2D 动作集

## 当前界面与选用原则

制作操作集中在工作台；资产库存提供独立的卡片内预览。画布只有 **一个 3D 模型 → 已选动作 → 序列帧** 三个节点，源模型和版本链折叠到来源详情。模型框只展示静止原始外观，可拖动观察，无功能按钮；模型选择和确认位于顶部。动作添加、目标/来源试播、Mixamo 中转在动作节点内，构图和洋葱播放在序列帧节点内。

- 库中存在、导入成功、任务成功、标记 character，都不意味着用户选用或质量通过。
- 新模型先在卡片内预览，再点“用于工作台”并输入工作台名称。模型自带动作不会自动全选。
- “添加动作”在节点内展开。点候选，在“已选动作”框内试播目标效果；展开“动作来源”点 ▶ 可看来源模型。再点候选的 ▶ 回到目标效果，实际加载完成后才允许“确认加入”。已选动作也直接点各行 ▶ 播放，没有重复的动作下拉框。
- 已选动作可以移除。下载 GLB 和出帧遵守同一个选用清单，不把隐藏动作重新装回。移除只更改选用范围，原文件保留；下载时生成只含已选片段的副本。
- 在序列帧框独立调整构图后，点“确认构图，生成 N 个动作”，才开始捕获。完成后右侧框内连续洋葱播放，保存为该模型的一套 2D 动作集。
- 序列帧各行动作用 ▶ 开播；与动作框独立，模型外观始终静止。历史动作集只在“历史序列帧”里待选。预览不自动选用；“保留这套序列帧”要求这些动作已在当前模型选用范围内。
- 资产库分模型、动作、序列帧，直接点封面在原卡片播放，无右侧单独预览区。库中资源不按“已选用/待选素材”分区，但制作选用记录仍独立。相同角色修订只显示一张卡片，版本折叠；同名动作保留真实来源。

quality 是质量记录；workspace-models 是用户选用范围；二者独立。AI 可准备候选、分析目标适用性，不能伪造人类已审核。当前历史双动作的初始选用来自用户原先明确提供并要求使用的拳击、行走转身，不代表新的质量评价。

## Skill 的工作台命令

| 命令 | 输入与边界 |
|---|---|
| asset-flow | {modelId?}。省略 ID 读取持久化当前模型。返回 selection、motions（已选）、candidateMotions、spriteSets（已保留）、candidateSets、来源链、任务和 URL。selection=null 表示仅查看候选，不启动生产或自动选用。 |
| workspace-select | {modelId,sourceHash,name?}，首次或归档后重新建立必须提供用户给出的 name（1–60 字）。只有用户已选定模型时调用。首次选用的 clipIndices=[]；已有模型复用原清单。不标质量通过。 |
| workspace-name | {modelId,name}，为旧台补名或改名，不改资产文件。 |
| workspace-draft | {modelId} 读取草稿；写入 {modelId,sourceHash,patch,clientId?,sequence?}，字段见调用参考。不改变选用/质量。 |
| workspace-selection | {modelId,revision,clipIndices?,spriteSetIds?}。revision 来自刚读到的 selection。两个数组分别是完整选用清单，允许空数组。片段属于当前模型；集合属于同模型同哈希且动作均已选用。并发变更报错，不能拿旧清单覆盖新选择。 |
| workspace-compose | {modelId,revision,candidate:{assetId,index,previewId,name?}}。确认新来源动作后调用。核对试播的源、目标、片段和哈希，只保留已选动作再加一个片段；返回 job。模型自带片段用 workspace-selection。 |
| workspace-complete | {jobId}。组合任务真实成功后调用。核对原选用 revision 与任务归属，原子切换为结果模型；派生版本不增加第二个模型节点。重复调用返回同一结果。 |
| workspace-export | {modelId,revision}。返回只含已选片段的 url/assetId，或整理副本的 job。先 wait 后下载真实输出。零动作可导出静止模型；不替换原工作台模型。 |
| workspace-onion | {modelId,clips,view,size,fps} 或 presetId。clips 必须均已选用，其余流程同 onion-preview；仅在确认构图后调用。 |
| flow-layout | {modelId,positions:{节点ID:{x,y}}}。仅保存位置，不改变选用和资产依赖。 |

组合任务 ID 持久保存在 selection.pendingJobId。刷新或换 AI 后继续 job/wait，再 workspace-complete；失败读真实 error，不自动换来源。等待中选用范围已变时，结果留为候选，不覆盖当前选择。通用 compose 仅适用于明确的加工请求，不用它绕开工作台选用范围。

## 2D 动作集与原帧

| 命令 | 输入与结果 |
|---|---|
| group-sprites | {selections:[{assetId,clipIndex}],name?}，1–30 段已有帧。核对模型 ID/哈希、相机、尺寸、帧率、渲染器、锚点一致；相同成员复用。创建集合不等于选用。 |
| sprite-set | {id}，返回源模型、帧包与哈希、构图、锚点、playback.order。 |
| sprite-playback | {id,order:["帧包ID:片段编号",...],repeat:true}，1–30 段，允许重复。只改验收顺序。 |
| onion-preview | {spriteSetId} 或明确的 modelId/clips/presetId、view/size/fps、selections。准备指定动作，不从全库任选，不自动加入工作台。 |

onion-preview / workspace-onion 的 state=preparing 携带真实 job，先 wait，成功后同参数重调，直至 ready 返回 result、spriteSet、uiUrl。失败读 error，修正后明确 retry:true。网页节点内播放，旧 panel=frames 链接也进入工作台。PNG 保留原坐标与颜色，前两帧青色、后两帧橙色，不重居中、不造过渡。

frames 返回逐段 PNG 包 outputs 和 spriteSetId。handoff 支持 spriteSetIds 或 sprite-set ref，展开原帧依赖与验收顺序。集合 JSON 不代替所有 PNG。

## 持久数据与迁移

- workspace-models 保存模型哈希、clipIndices、spriteSetIds、revision、派生版本与待完成任务；workspace-settings/active 保存当前模型。
- sprite-set.json 是不可变清单；sprite-playlists 保存顺序；flow-layouts 保存位置（当前布局版本 3）。均随数据库迁移，不能只复制 GLB 而丢掉选用关系。
- search 默认返回已选用，includeCandidates:true 才包括待选。selectionStatus 与 selectedForModels 供 AI 识别；在其他模型选过，也仍需当前目标试播。
- 已有依赖不可任意重连。连模型到动作是打开选择入口，连动作到序列帧是定位制作入口；确认后才生产。
- 使用 React Flow 12.12.0；这是本地功能界面，不是任意节点自动执行编排器，不新增后台收费 AI。

## 2026-10-09：名称、增量更新与恢复

- workspaces 保存独立 workspaceId、用户名字和 currentModelId。workspace-models 仍以具体模型版本保存选用，带 workspaceId。版本替换不会增加工作台条目，归档仅隐藏工作台，不删除源资产。
- workspace-drafts 按模型哈希保存 UI 草稿。浏览器先本地记忆，再 450ms 合并同步；只发送变动字段，clientId/sequence 阻止同客户端旧请求回写。pagehide 尝试补交，离线保留未同步字段，下次重连。
- 恢复范围：动作选择/出帧勾选、候选来源和搜索、三个镜头、播放进度/暂停、出帧尺寸帧率、画布位置缩放、已提交请求和当前动作集。实际 framePreset 与收费授权不由草稿替代。
- 完成动作组合前刷新草稿；服务按 motions 映射旧片段索引并继承工作台身份。预览复用明确 geometryPreserved 的网格与贴图，新增动作只取片段 GLB。真正切换工作台才重建对应预览。
- 旧版序列帧留在“此前版本的序列帧”，可以直接下载/播放，保留旧 sourceAssetId/sourceHash。不得把旧图片谎称为新版本重新渲染。
- sprite-set 的 downloadUrl 是整套 ZIP，包含动作集.json、使用说明和各动作原 ZIP；manifestUrl 才是纯 JSON。PNG、锚点、原帧时间不被打包过程改动。

## 与网页完全相同的资产库存

`library {kind:"model"|"motion"|"sprites",q?,offset?,limit?}` 为只读命令。模型按显式 modelFamilyId / modelRevisionOf / geometryPreserved 主来源链归组；结果含 familyId 和具体版本 ref。不能仅按名字、相同骨架或同面数合并。

动作列表的 ref 精确到来源资产与片段；封面来自该来源动作姿态，预览不能当目标模型兼容结论。序列帧库单列已有动作集和未归组原帧。封面与 GIF 属于派生缓存，随库迁移，不能反向覆盖模型和原 PNG。

## 无骨骼模型接回原工作台

asset-flow.model 包含 boneCount、rigState、riggingUrl。missing 时先走 upload 与网站绑定，参考“模型与动作”；不要持续排队同一个失败试播。导入 With Skin 时标记 riggingReturn，再经外观预览调用 rig-adopt。继承同一 workspaceId 和人类名称，原始无骨骼模型保留，新绑定版本的已选动作从空清单开始。文件里的来源动作仍可在候选中挑选，禁止自动加入。

模型命名由 model-name 管理；工作台命名由 workspace-name 管理。模型家族名称、绑定来源、工作台映射均存在同一数据库，随原有迁移打包，不以改名创建重复模型或空工作台。
