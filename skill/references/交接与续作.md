# 交接与跨项目续作

## 可追踪的需求

按名称 `plans:{q:"古代持刀士兵"}` 找回需求，避免依赖聊天记忆。plan-status 提供候选、缺口、任务和产物。更新一个动作选择用：

```json
{"id":"真实计划ID","motionSelections":{"walk":"motion:真实资产ID:0"}}
```

motions 默认按 key 合并；只有明确替换整个职责列表时加 replaceMotions=true。空的选择可置 null。无效 ref 返回具体缺口。计划任务以当前模型和动作选择摘要关联，旧分支任务仍保留审计，不能冒充新选择的完成结果。

上传、导回、试播、组装、序列帧请求携带 planId。网站导回可继承上传任务的 planId。queued/running 用 wait；失败看 error/code/nextAction；不要对所有问题都运行 doctor 或 retry。

## 状态怎么解释

- succeeded：该项处理完成，inspect 输出；不等于质量通过。
- needs_input：读 nextAction。Mixamo 的 artifactsReady=true 表示上传 FBX 已可用，随后需要官网步骤。
- failed/interrupted：保留已成功子项；读取具体原因后处理，frames 的 retry 复用成功项。
- cancelled：本地跟踪/处理已停；取消云端跟踪不等于云端订单取消。
- timedOut:true：等待窗口结束；若真实 state 仍 running，就继续等，不是制作失败。
- awaiting_quality_review：已有制作产物，应先检查它；不要因未标可复用而重新制作。

## 统一交付

handoff 接收 modelId、spriteSetIds、spritesIds、reviewIds 或 refs；附 planId、engine、motionMappings、rootMotionPolicy、unresolved、notes。生成独立资产，包含统一 JSON 和中文使用说明。指定 sprite-set 时会展开每段原帧包，并记录当前验收播放顺序；集合清单不是 PNG 本身。

motionMappings 每项 role/index 对应交付模型实际片段；可以带 loop 和用途说明。省略时按原片段列出，但 loop/rootMotion 为 unknown，不能凭动作名猜。交付含精确引用/哈希、原包许可链、帧清单/锚点约定、校对结论、待处理项。

调用者 AI 在目标项目中读取约定和既有动画控制器，复制已交付 GLB/PNG 包到正确资源目录，连接真实动画片段。模型朝向、单位、角色速度、循环、根运动、攻击命中窗口由游戏实际需求确定。交接包写着 gameIntegrationStatus=not_performed，不能把包已生成说成游戏已接入。

资产库迁移后，交接文件的绝对路径只是历史快照。用 libraryId/ref 重新 inspect 得到当前路径；不可搜索同名文件随意替代。

## 最短机械调用顺序

1. help → 读相关索引页。
2. search:{kind:"model",q:"士兵"} → inspect 一个候选；形象仍需选择时先展示。
3. search:{kind:"motion",q:"行走",modelId:所选模型ID}。
4. 将候选的 previewRequest 原样交给 preview → preview-status，直到终态。
5. 看目标播放；必要时 motion-quality 保存用途、证据与判断。
6. compose:{modelId:同一个模型ID,motions:[{ref:同一个动作ref}],planId:需求ID} → wait → inspect 输出。
7. 按需 frames / 洋葱皮流程；否则直接 handoff。
8. 返回真实文件与未完成项；用户要求接入时由当前项目 AI 接续。缺环节时按 asset-map.md 的缺口表处理。

所选 ID 来自本次真实响应，不能把文档占位符直接发送，也不能用一个素材示例代替用户的形象选择。
