## 一、服务目标

为游戏开发提供可积累的三维模型、已有动作、二维序列帧及其来源、质量和接入资料。主要使用者是开发游戏的 Codex；全局 `asset-workbench` Skill 负责发现与编排能力。中文网页负责看资产、挑选动作、取景、处理需要人的步骤。两者共用同一个资产库，不维护两份资产清单，不需要 GPT API。

典型需求是“为当前游戏做一个古代持刀士兵，配齐待机、移动、攻击、受击和倒地”。系统应先找已有合适模型供选择，找已有动作并在目标上试播，缺什么就明确补什么。不能把任意战术男性换名字当成古代士兵，也不能把空手拳击当成持刀挥砍。

二维需求在此基础上导出多个动作的透明序列图片。新增校对用于观察动作衔接、锚点一致性与画面漂移，不自动改动原始动作，不逐帧居中抹掉根运动。

## 二、范围与非目标

### 本期必须完成

1. 可供全局 Skill 检索和操作的共享资产服务；模型生成、动作组装、序列帧、任务续接形成闭环。
2. 面向新人的中文网页；模型选择、动作来源试播、Mixamo 人工交接、确认构图后导出。
3. 多动作序列帧的洋葱皮校对窗口、测量数据、可追踪的 Codex 判断。
4. Skill 内部分模块和索引；中文接入、使用、故障与交接文档。
5. Skill、程序、数据目录分开绑定；主动打开页面时清理旧空闲服务，避免重复进程。
6. 自包含迁移包格式：程序、Skill、数据库、原始包、成品和必要缓存。能恢复到指定程序/数据目录，保留资产库 ID，再重新绑定全局入口。

### 保持人工或按需接入的边界

- Mixamo 的登录、验证码、关节标记、网站选动作与下载仍是官网步骤。没有稳定官方 API 的前提下，不依赖抓取登录令牌或私有接口破解。
- 只有明确获准的具体生成任务才提交收费；本轮开发不额外消费生成 credits。
- 不承诺所有人形或所有比例都能自动重定向。已知骨架 FK 适配后仍需看握持、脚底与穿插；不支持的骨架转成熟工具处理。
- 缺动作不编造动作；多片段 GLB 不等于引擎中的上下半身混合或自动连招。
- 前端不偷偷调用付费语言模型。AI 判断由正在调用 Skill 的 Codex 执行；网页单独使用时可复制带报告 ID 的请求给 Codex。
- 游戏引擎接入由使用该 Skill 的 AI 在目标游戏项目执行，遵守项目约定；资产制作请求本身不修改某个无关游戏。
- 迁移不删除旧库，不打包私有账号 Key，不安装商业插件。依赖软件仍需在目标机器存在或按文档安装。

## 三、架构和所有权

```text
游戏项目中的 Codex
  → 全局 Skill：短入口 + 能力索引 + 中文参考 + 稳定命令脚本
  → 路径绑定与本机服务生命周期管理
  → 同一个 HTTP 服务 ← 中文 React 网页
       ├─ 资产目录与精确引用
       ├─ 需求计划、缺口、阶段和任务
       ├─ 动作预览/组装
       ├─ 模型生成适配器
       ├─ 序列帧捕获/编码
       └─ 洋葱皮证据和 AI 校对记录
           ↓
       SQLite + 原始包 + 不可变成品 + 可复用缓存
           ↓
       Blender / Three.js 捕获 / Pillow / Lux3D 官方运行时
```

- 前端：React、Radix、Three.js、Vite，常用页面中文；技术参数折叠。
- 服务：Node 26、Express、SQLite，同步记录读写，绑定本机地址。
- 本地重处理：Blender 子进程；序列帧通过同一个 Viewer 在本机 Chrome 逐帧捕获；Pillow 编码/打包/诊断。
- 队列：本地制作队列和编码队列分开，按真实片段/帧更新进度。预览有单独缓存状态。网页关闭不等于任务完成或取消。
- Skill 入口不存用户资产快照；每次检索读取活目录。只存能力说明和库地址绑定。
- 用户拥有原始模型、明确选定的动作、相机和角色用途；自动化不得通过推断覆盖这些已作出的选择。

## 四、数据结构与映射

### 资产

每个资产有 `id、name、kind、file、sha256、metadata、parents、source、license、quality、createdAt`。原始文件归档在 packages；成品保存在 assets；文件路径相对于数据目录。模型 metadata 包括顶点/三角面数、材质/图片、骨架层级/静止签名和动画片段。

| 引用 | 含义 | 主要关系 |
|---|---|---|
| model:ID | 一个精确模型版本 | 来源、前版、骨架、贴图、动作 |
| motion:ID:INDEX | 不可变 GLB 中指定片段 | 原始动作身份、展示载体、来源、试播 |
| skeleton:SIGNATURE | 同静止骨架签名的一组资产 | 骨骼层级、资产集合；不代表质量合格 |
| texture:ID:INDEX | 模型图片索引 | 内嵌图片或外部依赖 |
| sprites:ID | 一个序列帧包 | 来源模型哈希、片段、相机、时间、锚点 |
| image:ID | 原始参考图 | 可选生成输入 |
| review:ID（本轮新增） | 洋葱皮校对报告 | 源序列帧哈希、证据图、量测、AI 判断 |

用途 `usageRole`：character 为对外模型；motion-source 只作为动作来源展示；working 是历史/中间模型。默认模型列表只显示 character。改变用途会持久保存。

动作身份与展示载体分离：修复材质后可使用新版载体预览，但精确动作 ref 不自动替换。显式 motionOrigins 优先；旧来源不能证明时标未知，保留独立记录。不能仅凭动作数量或名字去重。

组合/删除动作形成新模型版本，保留原文件和源动作库；精确下载与推荐当前版本分别表达。删模型中的动作不等于删除动作来源。

### 需求计划和任务

plan 保存玩法约束、模型查询、候选、所选 modelId、动作职责和 selectedRef。plan-status 重新检索并给出缺口/后续命令和已关联 jobs。计划不是完整自动工作流引擎，候选也不代表适用性通过。

Job 状态为 queued/running/needs_input/interrupted/failed/succeeded/cancelled。记录真实阶段、进度、输入、输出、事件、异常、远端 taskId。只有 succeeded 的输出才算产物；部分失败保留已完成项。不要把远端等待伪装成百分比。

关键入库操作短事务提交：资产、版本关系、任务产物同步；productionKey 用于重复保存去重。引用中包含库 ID、文件哈希和不可变片段，支持换 AI 续接。

## 六、正在补齐的路径与生命周期设计

绑定配置放全局 Skill 的 `references/workbench.json`：projectRoot（程序）、dataRoot（数据）、baseUrl、protocolVersion、libraryId、可选依赖路径。当前程序与库仍位于 D 盘，不因拆分而自动搬动实际数据。

- location 输出绑定；doctor 读取库身份、服务和依赖；help 不必启动服务。
- 普通 search/compose 等命令自动启动或复用同库服务，不反复重启。
- 显式 open 表示“打开资产库界面”：若旧服务空闲，验证路径/库/PID 后关闭，等待退出，再启动一个隐藏进程；由调用者打开或复用 Codex 标签页。
- 仍有任务时返回真实活动任务并复用当前服务，不为“打开页面”强杀渲染。不启动第二个服务。
- stop 只管理已绑定同库服务。服务 nonce 存本地文件，不在健康响应公开；不同项目占用端口时报告冲突，不能按端口结束所有 Node。
- 数据目录独占服务记录、启动管理锁防重复；崩溃留下的记录只有确认原 PID 不存在时清理。
- 绑定新路径前检查数据库 ID、程序存在，先结束旧空闲服务。找不到库时不创建空库掩盖丢失。

上述路径和生命周期已完成装配并同步全局 Skill；实际 open 已完成旧进程退出、新进程启动和路径/库 ID 健康读取。迁移包采用同一绑定，实际换盘尚未执行。

## 七、迁移设计

输入为输出 ZIP 路径；默认完整包。执行前等待服务空闲并关闭，使用 SQLite backup 生成一致快照，不仅复制可能依赖 WAL 的主文件。包结构：

```text
迁移清单.json           包版本、库 ID、逐文件哈希、依赖、排除项
恢复说明.md             中文步骤、路径绑定、限制与故障恢复
runtime/               程序源码、构建网页、依赖锁、说明
skill/                 当前全局 Skill、入口脚本、中文参考
data/                  数据库快照、原包、成品、配置、必要缓存和历史
```

- 不含 node_modules、外部软件、账号 Key、临时 PID/启动锁和正在写入的日志；配置中的旧地址仅作历史，不作恢复目标。
- 打包按文件流写入，记录每项 SHA256 和长度；包完成才替换 .partial；原库不删。
- 恢复必须指定空的程序/数据目的目录，拒绝覆盖现有库。ZIP 条目必须限制到所选目录，禁止路径穿越和链接写入。
- 恢复核对清单、文件长度/哈希和数据库 libraryId；复制 Skill 到新程序的 skill 目录供安装。实际全局 Skill 仍由显式安装/绑定切换，不在解压完成前改掉旧地址。
- Node/Python/Blender/Chrome/Lux3D 运行时是外部依赖；恢复后 doctor 给出缺失项。依赖不全时不能宣称完成可用迁移。
- 旧工作目录中的绝对路径日志可保留用于审计；生产读取依赖相对 data 路径。缓存涉及绝对路径的记录需按字段迁移或失效，不盲目全文替换用户提示词。
- 本轮实现迁移工具和文档；用户尚未给实际新盘目标，不擅自移动整个库。实际迁移未执行要明确说明。

## 八、洋葱皮校对设计

### 输入与前置

有序选择 1–30 个已有 sprites 片段。一个动作可检查循环首尾或内部稳定；多动作按选择顺序检查连接。使用原 PNG，而非 GIF 或 AI 重绘。记录源资产 ID/SHA、片段编号、真实帧文件与时间。

若画面大小、源模型哈希、相机/渲染器不同，返回不可直接比较的原因；可以看原图，但不能把缩放/取景差异当姿态错位。缺少相机、pivot、源哈希的历史帧明确 unknown，必要时用统一构图重新出帧。

### 窗口与证据

- 2026-10-09 根据实际使用反馈简化：打开 2D 动作集即连续洋葱播放当前指定的全部动作，不再让人重新选动作或先配置报告。
- 当前帧保留原色，前两帧青色、后两帧橙色；固定锚点十字。支持慢放、暂停、进度拖动、顺序编辑与重复片段。播放顺序单独保存，原帧不移动。
- 精确指定比较帧继续由 Skill 的 pairs 支持；文件和 AI 判断折叠为可选详情。
- 报告生成动作内取样叠加、首尾连接叠加、接触表、边缘接触与位置轨迹；测量和报告进入共享库。
- 显示“量测完成 / AI 待判断 / AI 已判断”，不能把程序运行结束写成 AI 已通过。
- Codex 可通过全局命令获取证据文件，用图片查看能力判断，然后提交结论；网页独立用户通过复制精确请求启动此一步。

### 测量与判断语义

量测声明的 pivot 差值、alpha 轮廓框/中心/最低点随时间变化、边缘接触帧、接缝轮廓重叠与偏移。轮廓中心变化不等于根节点错误；最低点不是可靠脚掌接触；跳跃、冲刺和挥刀可有合理重心移动。

AI 结论必须指向证据图/帧，区分锚点配置、姿态不连续、主动根运动、裁切、疑似脚滑和无法判断。描述建议如换片段/统一取景/在引擎过渡/保持根运动，不自动重写源图或生成虚假过渡动作。

本期采用可解释的像素量测 + 调用者 Codex 看图；不引入姿态识别模型、付费 API 或后台常驻第二个 AI。AI 保存结果包含 evidenceHash，证据更新后旧结论不能冒充新结论。

## 九、Skill 解耦与中文文档

- SKILL.md 保持短入口，只放路由、共同约束、最短调用。
- 人读索引与机器可读能力索引对应：查库、模型/骨架/动作、3D 交接、2D 帧、校对、运行/迁移、故障恢复。
- API 字段在单一命令表和调用参考维护；CLI 与 MCP 同源，不各写另一份功能名单。
- 不把资产 ID 清单写入技能；search/inspect 精简检索优先于 state 全量导出。
- 中文文档覆盖安装/绑定/打开、输入请求、状态追踪、成功交付、失败下一步、模型适用性、网站人工交接、复用与迁移。
- 每次能力、接口或边界改变，同一修改同步索引、字段说明、进度和全局安装副本。文档更新是维护流程，不是假装存在一个自动持续写文档的后台 AI。

## 十二、资产工作流与 2D 动作集（2026-10-09 使用反馈后的当前实现）

## 十三、单一工作台与明确选用（2026-10-09 最新体验约束）

### 已实现结构

- 首页三节点：一个模型内嵌 Three.js 预览 → 已选动作 → 序列帧与洋葱播放。移除单独“添加动作/导出图片”页面；旧链接进入工作台。生成、资产库是辅助入口，预览回同一工作台。

## 十四、三个节点各自预览（2026-10-09 后续纠正）

- 模型选择、确认和折叠来源位于工作台顶部。已确认动作的下载位于动作框下方。模型选择不覆盖当前的动作范围。

## 十五、独立库存、卡片播放、工作台身份与恢复（2026-10-09 当前规则）

本节覆盖前文“全部预览只能去工作台”“已选用/待选素材分区”“双动作/三动作初始范围”的旧交互。实时数据库是资产与选用事实，不能按历史快照回滚。

### 资产库

三个独立目录：模型库、动作库、序列帧库。点击封面在该矩形卡片中预览，不另设右侧预览区或弹窗，不强制跳工作台。模型可观察静止外观；动作播放原来源模型；序列帧播放对应原 PNG 的 GIF、多动作可切换并在卡片内展开洋葱播放。生产装配仍在工作台内执行。

模型按显式家族与来源链归组：modelFamilyId → modelRevisionOf → 明确 geometryPreserved 的主父模型。相似名称、相同骨架、面数相同都不足以建立同一模型关系。当前战术角色旧的 Mixamo 回传已关联原 Lux3D 角色，同一角色的 23 个处理版本收在一张卡片；原文件和具体版本 ID 不变。动作伴随的演示网格不列为新角色。

封面按源 GLB 哈希、片段编号和封面版本缓存。缺封面时使用一个 320×320 渲染器逐项渲染真实姿态；用户播放优先，停止背景制封面，不同时运行全库渲染器。封面不是模型资产、不是目标适配或质量证据。历史无 GIF 的原帧由 sprite-preview 从 ZIP 补充，保留原文件、位置和时间。

### 稳定工作台和增量更新

workspaces 保存用户 name、workspaceId、currentModelId；workspace-models 保存具体版本的选择。工作台列表只出现活动且未替代的条目。此前收敛时保留 14 动作工作台并归档旧 8 动作工作台，资源未删除；后续用户已将其命名为“男主角”，另建“女主角”工作台。新的用户工作台应继续保留，不反复按旧快照清理。原自动名字要求人类补名，新的工作台必须人类输入 1–60 字名字，后续版本继续同一名字。

新增动作时保留原画布节点和已加载网格，使用轻量动画片段 GLB；只更新列表与相关动作。模型、动作、出帧三个镜头分开。真正切换另一工作台时，按稳定身份重建预览、恢复该台视角。已选片段与候选试播分开；没有增加人类未确认的动作。

workspace-drafts 保存模型哈希对应的相机、筛选、勾选、候选、播放位置、画布、出帧请求和动作集。浏览器即时缓存，450ms 合并写回；序号防旧回写。动作组合完成时原子继承身份与草稿，并按实际动作映射索引。上一版序列帧保留旧 sourceAssetId/hash，不冒充新产物。

新增全局命令 library、workspace-name、workspace-draft、generation-draft、sprite-preview。library 与网页用同一模型归组和动作来源规则；inspect 仍处理精确版本与片段。分类、封面和预览不会自动改变选用或质量。界面侧的 asset-covers 仅保存派生 PNG 缓存。

数据库内的 workspaces、workspace-drafts、generation-drafts、asset-covers、播放顺序与全部 assets/covers 均随既有迁移打包；Skill 绑定的程序/dataRoot/libraryId 机制不变。全局说明禁止只拷 GLB 后声称整库迁移完毕。

## 十七、模型命名与缺骨骼闭环

模型名称与工作台名称是两种独立信息。独立模型上传先弹出名称表单，批量独立文件逐个命名；GLTF/OBJ 依赖包只命名一个模型。生成表单增加独立名称输入并同步 generation-draft.modelName，报价签名包含名称。后端 import/quote 拒绝空名称和超过 60 字名称；图片参考和动作源保留各自导入规则。model-name 修改家族名称及版本前缀，不改文件、哈希、骨架、材质或工作台名称。

无骨骼模型在卡片标明“需先绑定骨骼”，在工作台先进入绑定入口，避免每次动作试播都才报错。upload 以原外形导出带贴图 FBX，相同准备规格复用既有任务。外部 Mixamo 登录、上传和关节标记仍由人工完成；此处不发第二次 Lux3D 模型生成请求，也没有新增自造骨骼/动作算法。

回传有专门用途 riggingReturn，保存原模型 ID/hash、上传任务与原始 FBX。With Skin 缺失时任务停在 needs_input，保留原文件；导入后可以在节点里看外观。rig-adopt 要求双方哈希、来源匹配、网格、骨骼及实际蒙皮权重；源有贴图而返回无贴图时拒绝接回。用户确认外观后，才把绑定结果作为同一家族新版本使用；原始模型保留，已有工作台沿用 workspaceId/名称/镜头/布局，新动作选用清单为空。导回姿态和来源动作均不自动作为已审核动作。

流程伪代码：

```text
独立模型导入/报价：校验用户给出的 name → 入库/报价 → 跟踪原 job
打开模型：读 boneCount → 有骨架可挑动作；缺骨架显示绑定入口
准备：upload(modelId, unrigged=true, textures=true) → 等 artifactsReady
网站：上传 → 标记关节 → 绑定 → 下载 With Skin
导回：import(handoffModelId, handoffJobId?, riggingReturn=true)
检查导回：有网格与骨骼 → 节点内预览 → 人类确认外观
接回：rig-adopt(双方 ID/hash, confirmAppearance=true)
事务：原文件保留 → 同模型家族 → 同工作台新版本 → 继续挑动作
```

rig-adopt 是接回外部结果，不表示本地实现了自动绑骨。当前女主角 GLB 实测 boneCount=0，准备 FBX 已完成，但官网绑定与 With Skin 导回尚待实际执行；不能把前端/后端构建成功当作此阶段已完成。
