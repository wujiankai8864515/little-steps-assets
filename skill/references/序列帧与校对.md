# 二维序列帧、姿态衔接与锚点校对

## 出帧

网页：工作台勾选已选用的 N 个动作，在序列帧框中独立调整构图，点击“确认构图，生成 N 个动作”。调整镜头不自动捕获；完成后右侧序列帧节点内直接洋葱播放，并归为同一模型的 **2D 动作集**。不跳转到另一个预览页。工作台出帧优先 workspace-onion，服务校验选用范围。依赖与调用见 [资产工作流](资产工作流.md)。

Skill：inspect 模型的 framingPresets；用户要求“所见即所得”时只使用相同模型哈希的已确认构图，没有则引导网页。用户明确同意默认取景时，frames 可传 viewMode=default；默认不保证整段不被裁切。一次 clips 1–30 个，每段最多 720 帧，捕获逐片段进行。

frames 返回 job；wait 逐项跟踪 items。批次失败仍保留成功 outputs，retry 复用成功项。PNG 是原 RGBA 交付，GIF 只是预览。所有帧固定画布和相机，不逐帧裁剪、居中、镜像或改速度。

## 洋葱皮校对

日常目视验收优先 `onion-preview`，只输入目标动作集，或明确模型、片段列表、已确认构图。工作台序列帧框内播放全部指定动作。前两帧青色、当前帧原色、后两帧橙色，叠加不改变原位置；动作行的 ▶ 用于指定起播片段，没有第二个动作选择器；播放、进度、速度和顺序均在框内。拖动动作标签或展开“调整播放顺序”可前移、后移、从播放列表移除、重复加入；顺序保存到资产库。“重新调整构图”停止洋葱播放器并返回本框的构图画面；模型框保持静止外观，已选动作框的播放不受影响。

需要 Codex 的细致判断时，再使用下面的证据流程：

1. review-options 列出已有序列帧及片段（一个包可能多片段）。按实际游戏转换顺序选择 1–30 个。
2. review-frames 输入 selections:[{assetId,clipIndex,loop:false}]、intent、rootMotionPolicy。
   - intent：direct 直接切换；blend 引擎允许混合；anchors 仅检查位置；loop 循环首尾。
   - rootMotionPolicy：preserve 保留位移；in_place 引擎希望原地；unknown 尚未确定。该字段是检查要求，不会重写动作。
   - 可选 pairs:[{fromAction:0,toAction:1,fromFrame:39,toFrame:0,kind:"transition"}] 精确检查实际切换帧；默认相邻动作末帧→首帧。loop=true 另检查该段首尾。
3. wait 到任务成功 → review-status:{id:输出ID}，取得 reportHash、evidence 的真实图片路径、原帧测量和意图。
4. 调用者 Codex **打开图片看实际证据**。不能把 metrics 输出成功当视觉质量通过。至少看实际使用的接缝图和各动作采样/叠加图，必要时查看 frames 中更多单帧。
5. review-result 保存中文结论。引用 reportHash 和 evidence.id；checks 分别为 anchors、clipping、continuity、footSlip，每项 pass/issue/not_assessed。总体 verdict 为 usable_with_notes、needs_adjustment、inconclusive。

请求例（替换 ID/哈希和证据为本次真实返回值）：

```json
{
  "id":"报告ID","reportHash":"本次reportHash","reviewer":"Codex",
  "verdict":"needs_adjustment",
  "checks":{"anchors":"pass","clipping":"pass","continuity":"issue","footSlip":"not_assessed"},
  "summary":"锚点记录一致，直接切换时手臂姿态跳变。",
  "observations":[{"evidence":["transition-0"],"issue":"抬手姿态与下一动作不连续","suggestion":"选择更接近的切换帧，或按玩法允许的方式在引擎中混合。"}],
  "limitations":"二维轮廓不能证明足底接触，脚滑尚未判断。"
}
```

网页默认提供连续洋葱播放，原先逐对挑两帧的复杂表单已移除。精确比较帧仍可由 Skill 的 pairs 指定（最多 60 组）。节点内折叠的“资产文件与详细校对”中可“复制当前顺序给 Codex”；其中包含本次实际播放顺序，允许相同动作多次出现。调用者重新生成对应顺序的证据后判断；不能把以前顺序的结论当作本次验收。网页没有隐藏 GPT API。

## 判断边界

- pivot 是原画布左上角起算的归一化游戏锚点；同一固定投影的根原点可以保持不动，同时身体正常前后移动。
- 轮廓框中心不是人体重心或根骨。最低不透明像素不是可靠脚掌落地点。
- 同模型哈希、相机、渲染器、尺寸和有效锚点齐全时才做可靠跨动作比较；不同/缺失时返回原因，建议统一构图再出帧。
- 贴边帧、空帧是线索。脚滑、腾空、挥砍重心移动要结合玩法与原动画；看不清就 not_assessed。
- 不自动逐帧重居中“修复”主动根运动；不生成虚构衔接动作。可以建议换来源、换切换帧或游戏中平滑过渡。

判断保存在共享资产库，后续 inspect review / handoff 可取回。量测、AI 判断与人类验收是三个不同事实。

## 资产卡片与下载

序列帧库是独立目录，点击封面就在本卡片内播放；多动作集可点各行 ▶，洋葱播放也在卡片内展开。查看库存不切换工作台。

完成后的工作台、资产卡片均有整套 ZIP 下载。`sprite-set` 返回 downloadUrl（整套 ZIP）和 manifestUrl（仅 JSON）。ZIP 收录原动作包、共同构图/锚点/来源与播放顺序，不能只把 sprite-set.json 当作所有图片交付。

历史 sprites 若没有 GIF，可调用 `sprite-preview {assetId}`；准备中返回 job，wait 后再次读资产或同参请求。此操作只从原 ZIP 中的 PNG 生成预览，不重新出帧、不改像素位置。失败需要显式 retry:true，不自动重复循环。
